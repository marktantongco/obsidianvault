# Compounding Memory (raw → wiki → index)

Replace per-session recap with an accumulated, LLM-maintained markdown wiki: raw sources stay immutable, the model distils them into cross-linked wiki pages, and a single flat index keeps retrieval cheap.

## Notes

### 2026-11-12 — source: _raw/_archived/2026-11-12-claude-memory-compounding-guide.md
Pattern traced to Andrej Karpathy: have an LLM maintain a plain-markdown personal wiki instead of building a RAG/vector pipeline.

Three layers, each with one rule:

- **`_raw/` (input, immutable)** — transcripts, pastes, emails. A wrong claim is corrected by a *new* raw note, never by editing the original; that keeps provenance intact.
- **`wiki/` (the brain)** — model-maintained pages (`people/`, `projects/`, `decisions/`, `concepts/`, `_moc/`). Append-only `## Notes` log per page; contradictions get a `> [!contradiction]` callout rather than a silent overwrite; missing link targets become stubs, never deleted links.
- **`output/` (deliverables)** — finished artefacts pulled from the wiki.

The efficiency layer is `00-INDEX.md`: a flat map regenerated by walking *frontmatter only*, so a question costs the index (≈800–1500 tokens) plus the 2–5 pages it points at, not a full-vault scan. Vault size stops mattering until the index itself gets expensive — roughly 100–150 pages, beyond which you add a vector cold-archive and keep Obsidian for active knowledge.

Cadence that keeps it alive: `/ingest` (manifest-driven change detection, so already-seen files are skipped), `/ask` (index-first answering with citations), `/lint` every 1–2 weeks for orphans, stale stubs, broken wikilinks and unresolved contradictions. The failure mode is silent drift, not a single big break.

Adapted here to coexist with the vault's v7.6 buckets (`01_WORK/`…`06_STATE/`), which remain canonical: wiki pages cross-link into them instead of replacing them.
